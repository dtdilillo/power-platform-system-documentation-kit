# How to use this kit

## For a new system

1. Copy `templates/MASTER-outline.md` to a working document **outside** this public repo if the system is live and named.
2. Copy the three CSV files in `templates/` into that same working folder.
3. Follow `docs/00-method.md` in order. Do not skip the conflict register.
4. When a cell cannot be filled from evidence, write `UNRESOLVED` and the evidence you still need.
5. Run `docs/07-privacy-and-public-exposure.md` before any file is committed here.

## For this repository itself

Public commits belong only to:

- method pages under `docs/`
- blank templates under `templates/`
- the generic case study under `examples/municipal-posting-board/`

Do not add a fourth example that is the real employer system with the names changed by one letter.

## For job applications

Safe to link: this repository URL.

Safe résumé line:

> Documented a Power Apps / SharePoint / Power Automate posting lifecycle as an evidence-bounded system reference (source of truth, status model, field dictionary, unresolved register). Method: github.com/dtdilillo/power-platform-system-documentation-kit

Do not attach a live MASTER file to an application.

Do not put grant-dollar figures or inquiry-reduction figures on this repository. Those belong on the duty lines they already live on.

## For keeping the repo current

One small commit before an application week is enough:

- tighten a template column
- add a test case to `docs/08-test-plan-template.md`
- add a rollover checklist row

Do not commit the answer to a live-system gap. Commit the template improvement the gap forced.
